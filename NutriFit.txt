PROJECT PURPOSE AND PRODUCT VISION
======================================================================

App name: NutriFit Android application ID / package name:
com.dietplanner Initial platform: Android first; keep architecture ready
for iOS later. Application type: React Native CLI mobile application.
Primary audience: Pakistan and India. Primary purpose: Help users manage
their diet, weight and nutrition with realistic South Asian meals that
fit their food budget.

differentiator is: - Desi/Pakistani/Indian meal recommendations. - Diet

the source of truth for food nutrition and prices. AI may select and
explain database-backed meals, but the backend must calculate and
validate totals.

Test RLS using at least two separate test users. Verify that one user
cannot read or modify another user’s records.

Do not assume hiding a button is security.

10. GEMINI AI AND SECURE BACKEND
======================================================================

Use Supabase Edge Functions for AI requests. The mobile application must
never call Gemini with a secret key.

Create functions such as: - generate-diet-plan - replace-meal -
suggest-food-alternatives - explain-meal

Use the current supported Gemini API model available to the configured
project. Keep model name configurable and document it. Handle free-tier
quotas, rate limits, timeouts and provider errors.

AI request flow: 1. Authenticate the Supabase user. 2. Validate request
and user ownership. 3. Read profile, goal, allergies, preferences and
budget from the database. 4. Calculate a safe calorie and macro target
using validated backend logic. 5. Fetch eligible food items and current
city-specific prices. 6. Send only relevant database-backed options and
constraints to Gemini. 7. Ask Gemini to return strict structured JSON
containing selected food IDs, portions, meal grouping and explanations.
8. Validate every returned food ID against the supplied eligible
database entries. 9. Reject unknown food IDs, invalid quantities,
allergens and unsupported ingredients. 10. Calculate nutrition and cost
on the server from database values. 11. Check budget and nutritional
constraints. 12. Save the validated plan in Supabase. 13. Return the
saved plan to the app.

Do not trust AI-generated prices, calories, macros or user IDs.
Recalculate these values from trusted database records.

If a price is missing or stale: - Mark it unavailable or stale. - Do not
invent a price. - Ask for city or show a transparent estimate only if a
documented fallback source exists. - Explain uncertainty to the user.

Add rate limiting or another reasonable abuse-control mechanism. Avoid
logging secrets or sensitive health data.

11. NUTRITION AND FOOD DATA RULES
======================================================================

Build a starter catalogue of commonly eaten Pakistani and Indian foods,

Examples: - Wheat flour / atta. - Roti and chapati. - Rice. - Daal

explicit. - Clearly distinguish cooked and uncooked quantities.

Price data: - Prices vary by country, city, season and vendor. - Store
observation date, quantity, unit, source and currency. - Do not present

it unavailable rather than fabricate a value.

Check licensing and reuse conditions before importing external nutrition
datasets into a commercial app.

12. DIET CALCULATION AND SAFETY
======================================================================

Use validated, documented nutrition calculation methods. Keep
calculation logic separate from Gemini prompts.

-   Calculate energy needs using an appropriate validated formula and
    user inputs.
-   Apply conservative, explainable goal adjustments.
-   Do not recommend extreme calorie deficits or unsafe weight changes.
-   Account for activity level.
-   Do not assume all users have the same protein target.
-   Consider age and special circumstances.
-   Do not present the app as a medical professional.
-   Provide appropriate guidance to consult a qualified dietitian/doctor
    for medical conditions, pregnancy, eating disorder history, minors
    or other higher-risk cases.
-   Ask about allergies and strictly exclude allergenic foods.
-   Never let an AI suggestion override a safety restriction.

Clearly label targets as estimates, not diagnoses or medical
prescriptions.
